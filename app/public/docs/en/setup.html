1. Overview

EntEdit uses a SPARQL-compatible graph database to store and query RDF data. The recommended database is Ontotext GraphDB, which is included in the Docker installation. This guide starts with installing and running EntEdit on your own machine, and moves on to your own data, additional databases and hosting — from the basics to the more advanced.

If you just want to try EntEdit, you can skip this guide — a read-only online demo with sample bibliographic data is available at entedit.org/?demo, no installation required.

2. Installing and running EntEdit

Prerequisites

  • Docker and Docker Compose — installed and running on your machine.
  • Nothing else. Everything a standard installation needs is published on Docker Hub, including the data that initialises the database.
  • The EntEdit project files are needed only if you want to change the vocabulary, the sample data or the search indexes — clone the repository (git clone https://github.com/trondaal/EntEdit.git) or download it as a ZIP from the GitHub page.
Tip: Docker Desktop (available for Windows, macOS, and Linux) includes both Docker and Docker Compose.

Starting EntEdit

Start the whole system with a single command that you run in a terminal:

docker compose -f oci://docker.io/trondaal/entedit-compose:latest up -d
Where do I type this? In a terminal — Terminal on macOS and Linux, Command Prompt or PowerShell on Windows. If you would rather not leave Docker Desktop, it has a terminal built in: click the Terminal button in the bottom-right corner of the window, next to the version number, and paste the command there.
Note: Compose lists the variables the project uses and asks "Do you want to proceed with these variables? [Y/n]" — press Enter. Add -y to the command to skip the prompt, which is what you want when scripting the installation.

This starts three services:

Service URL Purpose
Web application http://localhost/entedit/ The EntEdit user interface (served by nginx)
GraphDB http://localhost:7200 The graph database (GraphDB Workbench for administration)
Initialization — A one-time service that creates the repository and imports data

Open http://localhost/entedit/ and configure EntEdit with the endpoint URL http://localhost/graphdb/repositories/EntEdit.

Note: The first time you run docker compose up, the initialization service will create the GraphDB repository, import vocabulary files and test data, and set up the full-text search indexes. This may take a minute or two.

The first start automatically pulls the pre-built images from Docker Hub — the web application from trondaal/entedit and the vocabulary, sample data and repository definition from trondaal/entedit-init — so no local build or Node.js installation is needed. GraphDB data is persisted in a Docker volume and survives restarts.

Does up fail with "port is already allocated"? Another program already uses port 80 or 7200. See Port 80 or 7200 already in use under Troubleshooting.

Stopping, updating and other commands

Everything above came from Docker Hub, including the Compose file itself, which is published there as an OCI artifact. That is why nothing had to be downloaded — and it also means there is no Compose file in your folder for later commands to read. Repeat the same -f oci://... reference each time:

  • Stop the services: docker compose -f oci://docker.io/trondaal/entedit-compose:latest down
  • Update to the newest published images: docker compose -f oci://docker.io/trondaal/entedit-compose:latest pull
  • See what the services are doing: docker compose -f oci://docker.io/trondaal/entedit-compose:latest logs -f

If you would rather have a file on disk — or if your version of Docker Compose does not understand oci:// — download the single Compose file into a folder of its own and leave the -f oci://... part out of every command. A checkout of the repository works the same way: run the commands in the project root. 

curl -O https://raw.githubusercontent.com/trondaal/EntEdit/main/docker-compose.yml
docker compose up -d

3. What the installation contains

The initialization service performs three phases:

  1. Repository creation — Creates a GraphDB repository named EntEdit with RDFS-Plus reasoning enabled.
  2. Data import — Loads all RDF files from two directories:
    • database/types/ — Vocabulary and ontology files (RDA properties, class definitions, controlled value lists)
    • database/testdata/ — Sample bibliographic entities (works, expressions, manifestations, agents). These are imported into the named graph http://oslomet.no/abi/examples so the examples can be managed independently of the vocabulary.
  3. SPARQL updates — Executes the Lucene full-text search connector definitions from database/lucene_connectors/, which power the Search tab.

4. Using your own data

The simplest way to load your own RDF data is from EntEdit itself: click the Import button in the application header, choose a .ttl, .nt, or .rdf file, and click Import. Imported triples are appended to the repository; existing data is not replaced.

You can also import through GraphDB Workbench:

  1. Open http://localhost:7200 in your browser and select the EntEdit repository in the repository menu at the top right.
  2. Go to Import and click Upload RDF files — or Get RDF data from a URL for a file on the web.
  3. Import the files. The search indexes pick up new data automatically.

The data should use the RDA vocabulary described in section 5; the files in database/testdata/ show the expected structure. To keep your own work apart from other data, put it in a repository of its own — see Additional repositories.

5. The vocabulary and ontology

EntEdit takes its classes, properties, controlled values and display configuration from the vocabulary files in database/types/. Every repository EntEdit works with needs all three folders:

Directory Contents
database/types/entedit_profile/ The EntEdit application profile — defines which classes and properties are active, their display order, and status. This is required.
database/types/rda_vocabulary/ The RDA (Resource Description and Access) ontology — class and property definitions with labels in multiple languages.
database/types/term_vocabularies/ Controlled value lists — languages, content types, media types, carrier types, work types.
Important: All three directories must be imported. Without the EntEdit profile, no classes or properties will appear in the application. Without the RDA vocabulary, labels will be missing. Without the term_vocabularies, controlled value dropdowns will be empty.

Ontology requirements

EntEdit expects certain conventions in the ontology to determine which classes and properties to display and how to order them:

Predicate Purpose
entedit:status Must be set to an active status value for a class or property to appear in the application. Classes and properties without this predicate are hidden.
entedit:order A numeric value that controls the display order of properties within the editor. Lower values appear first.
entedit:linguistic Set to false on a data property whose values are not natural language (dates, numbering, measurements, identifiers). The editor then offers no language selector for it. Properties without the annotation count as linguistic.
rdfs:domain Standard RDFS. Used to determine which properties are available for a given class.
rdfs:range Standard RDFS. Used to determine what values are valid for object properties.
rdfs:label Used to display human-readable names for classes, properties, and entities. Should be provided in both English and Norwegian for full bilingual support.

The vocabulary files provide a working example of how these predicates are used with the RDA ontology. If you are building your own ontology, use them as a reference.

6. Additional repositories

One GraphDB can hold several repositories, each with its own data. With the Docker installation you can add a repository next to EntEdit — for example to explore one of the example collections — and switch EntEdit between them. Your work in EntEdit is not affected. Everything you need is on GitHub:

What Where on GitHub
Vocabulary (required) database/types/ — three folders: entedit_profile, rda_vocabulary, term_vocabularies
Search indexes database/lucene_connectors/ — two SPARQL updates
Example collections data/ — Ballard, Bradbury, Christie, Golding, Grass, Hamsun, McCarthy, Tolkien and Twain, one Turtle file each

Creating a repository

  1. Open GraphDB Workbench at http://localhost:7200 (or the port you set with GRAPHDB_PORT).
  2. Go to Setup → Repositories → Create new repository → GraphDB Repository. Give it an ID, for example Hamsun, choose the ruleset RDFS-Plus (Optimized), tick Disable owl:sameAs, and click Create.
  3. Select the new repository in the repository menu at the top right of the Workbench. Imports and queries always go to the selected repository.
  4. Vocabulary: download the project from GitHub (Code → Download ZIP) and unpack it. In Import, click Upload RDF files, select all the files in one of the three folders under database/types/, and import them. Repeat for the other two folders.
  5. Collection: in Import, click Get RDF data from a URL and paste the file's raw address, for example https://raw.githubusercontent.com/trondaal/EntEdit/main/data/Hamsun.ttl. Several collections can go into the same repository.
  6. Search indexes: open each file in database/lucene_connectors/ on GitHub, paste its contents into SPARQL in the Workbench and run it. The indexes cover data imported before and after.

Switching EntEdit to another repository

The button at the top of EntEdit shows the name of the repository in use. Click it, change the end of the SPARQL Endpoint URL to the new repository ID — http://localhost/graphdb/repositories/Hamsun — and click Save. Switch back the same way with …/repositories/EntEdit. The graph visualization follows the repository EntEdit is using.

Users and security

In the Docker installation GraphDB security is off: anyone who can reach the machine's port 80 or 7200 can read, change and delete the data. You can switch it on in the Workbench under Setup → Users and Access by toggling Security, then log in as admin (default password root — change it straight away). There you can add users and give each one read or write access per repository.

EntEdit then needs access too. Either enable Free access and give it read and write rights to the repositories EntEdit should use, or enter a username and password under Username and Password in EntEdit's settings — they are kept only for the browser session.

Users who are logged in to the Workbench can also configure the graph visualization, for example which relationships and label languages it shows; their settings are used whenever EntEdit opens the graph.

7. Hosting GraphDB yourself

Instead of the Docker installation, EntEdit can use a GraphDB you run yourself — a standalone installation, or a server shared by a class or an organisation. The repository is set up exactly as in section 6: create it with the RDFS-Plus (Optimized) ruleset, import the vocabulary and your data, and run the search index updates, using the Workbench at your server's address. For many repositories at once, for example one per student group, see Provisioning many repositories in ADVANCED.md.

Tip: If you skip the search indexes, the Entity Browser still works — you can browse and edit entities normally. Only the Search tab requires the Lucene connectors.

Connecting EntEdit to the server

There are two working arrangements, and the choice decides what you have to configure.

GraphDB proxied under the same origin as the app — for example the app at https://example.org/entedit/ and the database at https://example.org/graphdb/repositories/EntEdit — is the better option: no CORS, no port number in the endpoint, and it keeps working when you add HTTPS. Two details need care:

  • The Workbench serves <base href="/">, so when it is reached under a sub-path its assets resolve against the site root and fail to load, leaving an unstyled page. Either set graphdb.external-url (plus graphdb.vhosts if GraphDB is reachable at several addresses) on the GraphDB server, or rewrite the tag in the proxy — Substitute in Apache, sub_filter in nginx.
  • Keep the SPARQL path out of that filter. Rewriting the response means disabling upstream compression, which you do not want for query results: match /graphdb/repositories/ in its own rule and proxy it untouched.

GraphDB on its own host or port needs no proxy configuration at all, as long as CORS is enabled on the GraphDB server. The Workbench then sits at the root of its own origin and the graph visualization works as-is. The only difference is that each user has to choose their repository once in the Workbench, because EntEdit can pre-select it only when both are served from the same origin.

On a shared server, switch GraphDB security on and give each user or group access to its own repositories, as described under Users and security.

8. Development setup

For local development of the EntEdit web application (without Docker for the frontend):

  1. Make sure you have Node.js 20+ installed.
  2. Start a GraphDB instance (either via Docker or a standalone installation) with the EntEdit repository.
  3. Install dependencies and start the dev server: 
    cd app
npm install
npm run dev
  4. Open http://localhost:5173 in your browser.

Use the endpoint URL http://localhost:7200/repositories/EntEdit, pointing straight at your own GraphDB. The Vite development server also proxies /graphdb requests to http://localhost:7200, but prefer the direct URL: the graph visualisation opens GraphDB Workbench, which renders correctly only when it is reached at the root of its own origin. Going direct also leaves your GraphDB installation untouched — EntEdit never writes to Workbench settings across origins.

Tip: If you are only developing the frontend, you can start just the GraphDB service with docker compose up graphdb graphdb-init -d and run the web app locally with npm run dev.

Project structure

The relevant directories in the EntEdit repository:

EntEdit/
├── app/ ← Web application (incl. nginx + proxy config)
├── data/ ← Example collections (not part of the installation)
├── database/
│ ├── types/ ← Vocabulary files (loaded into GraphDB)
│ ├── testdata/ ← Sample RDF entities (examples graph)
│ └── lucene_connectors/ ← Lucene full-text index definitions
├── docker/
│ └── graphdb/ ← Repository config + init script
└── docker-compose.yml

9. Troubleshooting

Port 80 or 7200 already in use

If another program on your machine — a web server, IIS, another GraphDB — already uses port 80 or 7200, up fails with "port is already allocated" or "address already in use". Choose other ports with the variables ENTEDIT_PORT (the web application, default 80) and GRAPHDB_PORT (GraphDB Workbench, default 7200): 

ENTEDIT_PORT=8080 docker compose -f oci://docker.io/trondaal/entedit-compose:latest up -d

In PowerShell, run $env:ENTEDIT_PORT=8080 first and then the command without the variable; in Command Prompt, use set ENTEDIT_PORT=8080. The application is then at http://localhost:8080/entedit/ and its endpoint is http://localhost:8080/graphdb/repositories/EntEdit — the port is the only thing that changes. Set the variable every time you run up, otherwise the application moves back to port 80.

EntEdit cannot connect to localhost:7200

GraphDB Workbench lives at http://localhost:7200 and is where you administer the database, but it is not the address EntEdit should use as its endpoint. A browser treats port 7200 as a different site — a different origin — from EntEdit itself, and blocks the requests with a CORS error. The address http://localhost/graphdb/... goes through nginx, which forwards the request to GraphDB server-side, so the problem never arises.

No classes or properties appear

The repository lacks the vocabulary, or part of it. Import all three folders of database/types/ into it, as described in section 5.

The Search tab finds nothing

The repository has no search indexes. Run the two updates in database/lucene_connectors/ in the Workbench's SPARQL view with the repository selected; they index the data that is already there.

The Workbench shows another repository's data

The Workbench works on the repository selected in its menu at the top right, independently of EntEdit. Select the right one there before importing or querying.
