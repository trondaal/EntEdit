1. Oversikt

EntEdit bruker en SPARQL-kompatibel grafdatabase for lagring og spørring av RDF-data. Den anbefalte databasen er Ontotext GraphDB, som er inkludert i Docker-installasjonen. Guiden begynner med å installere og kjøre EntEdit på din egen maskin, og går deretter videre til egne data, flere databaser og drift — fra det grunnleggende til det mer avanserte.

Hvis du bare vil prøve EntEdit, kan du hoppe over denne guiden — en skrivebeskyttet nettdemo med bibliografiske eksempeldata er tilgjengelig på entedit.org/?demo, ingen installasjon nødvendig.

2. Installere og kjøre EntEdit

Forutsetninger

  • Docker og Docker Compose — installert og kjørende på maskinen din.
  • Ingenting mer. Alt en vanlig installasjon trenger er publisert på Docker Hub, inkludert dataene som initialiserer databasen.
  • EntEdit-prosjektfilene trengs bare hvis du vil endre vokabularet, eksempeldataene eller søkeindeksene — klon prosjektet (git clone https://github.com/trondaal/EntEdit.git) eller last det ned som ZIP fra GitHub-siden.
Tips: Docker Desktop (tilgjengelig for Windows, macOS og Linux) inkluderer både Docker og Docker Compose.

Starte EntEdit

Start hele systemet med én kommando som du kjører i et terminalvindu:

docker compose -f oci://docker.io/trondaal/entedit-compose:latest up -d
Hvor skriver jeg dette? I et terminalvindu — Terminal på macOS og Linux, Ledetekst (Command Prompt) eller PowerShell på Windows. Vil du helst slippe å forlate Docker Desktop, har programmet en innebygd terminal: klikk Terminal-knappen nederst til høyre i vinduet, ved siden av versjonsnummeret, og lim inn kommandoen der.
Merk: Compose viser variablene prosjektet bruker og spør «Do you want to proceed with these variables? [Y/n]» — trykk Enter. Legg til -y i kommandoen for å hoppe over spørsmålet, noe du vil ha når installasjonen skal skriptes.

Dette starter tre tjenester:

Tjeneste URL Formål
Webapplikasjon http://localhost/entedit/ EntEdit-brukergrensesnittet (servert av nginx)
GraphDB http://localhost:7200 Grafdatabasen (GraphDB Workbench for administrasjon)
Initialisering — En engangstjeneste som oppretter datalageret (repository) og importerer data

Åpne http://localhost/entedit/ og konfigurer EntEdit med endepunkt-URL-en http://localhost/graphdb/repositories/EntEdit.

Merk: Første gang du kjører docker compose up, vil initialiseringstjenesten opprette GraphDB-datalageret, importere vokabularfiler og testdata, og sette opp fulltekstsøkeindeksene. Dette kan ta et minutt eller to.

Første oppstart henter automatisk de ferdigbygde imagene fra Docker Hub — webapplikasjonen fra trondaal/entedit, og vokabularet, eksempeldataene og repositorydefinisjonen fra trondaal/entedit-init — så ingen lokal bygging eller Node.js-installasjon er nødvendig. GraphDB-data lagres i et Docker-volum og overlever omstarter.

Feiler up med «port is already allocated»? Et annet program bruker allerede port 80 eller 7200. Se Port 80 eller 7200 er allerede i bruk under Feilsøking.

Stoppe, oppdatere og andre kommandoer

Alt over kom fra Docker Hub, også selve Compose-filen, som er publisert der som et OCI-artefakt. Det er derfor ingenting måtte lastes ned — men det betyr også at det ikke ligger noen Compose-fil i katalogen din som senere kommandoer kan lese. Gjenta derfor den samme -f oci://...-referansen hver gang:

  • Stoppe tjenestene: docker compose -f oci://docker.io/trondaal/entedit-compose:latest down
  • Oppdatere til de nyeste publiserte imagene: docker compose -f oci://docker.io/trondaal/entedit-compose:latest pull
  • Se hva tjenestene gjør: docker compose -f oci://docker.io/trondaal/entedit-compose:latest logs -f

Vil du heller ha en fil på disken — eller forstår ikke din versjon av Docker Compose oci:// — kan du laste ned den ene Compose-filen til en egen katalog og sløyfe -f oci://... i alle kommandoene. Fra en klone av prosjektet fungerer det på samme måte: kjør kommandoene i rotkatalogen. 

curl -O https://raw.githubusercontent.com/trondaal/EntEdit/main/docker-compose.yml
docker compose up -d

3. Hva installasjonen inneholder

Initialiseringstjenesten utfører tre faser:

  1. Oppretting av datalager — Oppretter et GraphDB-datalager (repository) med navnet EntEdit med RDFS-Plus-resonnering aktivert.
  2. Dataimport — Laster inn alle RDF-filer fra to kataloger:
    • database/types/ — Vokabular- og ontologifiler (RDA-egenskaper, klassedefinisjoner, kontrollerte verdilister)
    • database/testdata/ — Eksempler på bibliografiske entiteter (verk, uttrykk, manifestasjoner, agenter). Disse importeres til den navngitte grafen http://oslomet.no/abi/examples slik at eksemplene kan håndteres uavhengig av vokabularet.
  3. SPARQL-oppdateringer — Kjører Lucene-fulltekstsøkekoblingsdefinisjonene fra database/lucene_connectors/, som driver Søk-fanen.

4. Bruke egne data

Den enkleste måten å laste inn egne RDF-data på, er fra EntEdit selv: klikk Importer-knappen i applikasjons-headeren, velg en .ttl-, .nt- eller .rdf-fil, og klikk Importer. Importerte tripler legges til i datalageret; eksisterende data erstattes ikke.

Du kan også importere gjennom GraphDB Workbench:

  1. Åpne http://localhost:7200 i nettleseren og velg EntEdit-datalageret i datalagermenyen øverst til høyre.
  2. Gå til Import og klikk Upload RDF files — eller Get RDF data from a URL for en fil på nettet.
  3. Importer filene. Søkeindeksene fanger opp nye data automatisk.

Dataene bør bruke RDA-vokabularet som er beskrevet i seksjon 5; filene i database/testdata/ viser forventet struktur. Vil du holde ditt eget arbeid adskilt fra andre data, legger du det i et eget datalager — se Flere datalagre.

5. Vokabularet og ontologien

EntEdit henter klassene, egenskapene, de kontrollerte verdiene og visningskonfigurasjonen fra vokabularfilene i database/types/. Hvert datalager EntEdit arbeider mot, trenger alle tre mappene:

Katalog Innhold
database/types/entedit_profile/ EntEdit-applikasjonsprofilen — definerer hvilke klasser og egenskaper som er aktive, visningsrekkefølgen og status. Denne er påkrevd.
database/types/rda_vocabulary/ RDA-ontologien (Resource Description and Access) — klasse- og egenskapsdefinisjoner med labels på flere språk.
database/types/term_vocabularies/ Kontrollerte verdilister — språk, innholdstyper, medietyper, bærertyper, verktyper.
Viktig: Alle tre katalogene må importeres. Uten EntEdit-profilen vil ingen klasser eller egenskaper vises i applikasjonen. Uten RDA-vokabularet vil labels mangle. Uten termvokabularene vil nedtrekkslistene for kontrollerte verdier være tomme.

Ontologikrav

EntEdit forventer visse konvensjoner i ontologien for å bestemme hvilke klasser og egenskaper som skal vises, og hvordan de skal sorteres:

Predikat Formål
entedit:status Må settes til en aktiv statusverdi for at en klasse eller egenskap skal vises i applikasjonen. Klasser og egenskaper uten dette predikatet er skjulte.
entedit:order En numerisk verdi som styrer visningsrekkefølgen til egenskaper i editoren. Lavere verdier vises først.
entedit:linguistic Settes til false på en dataegenskap der verdiene ikke er naturlig språk (datoer, nummerering, mål, identifikatorer). Editoren viser da ingen språkvelger for den. Egenskaper uten merkingen regnes som språklige.
rdfs:domain Standard RDFS. Brukes til å bestemme hvilke egenskaper som er tilgjengelige for en gitt klasse.
rdfs:range Standard RDFS. Brukes til å bestemme hvilke verdier som er gyldige for objektegenskaper.
rdfs:label Brukes til å vise lesbare navn for klasser, egenskaper og entiteter. Bør oppgis på både engelsk og norsk for full tospråklig støtte.

Vokabularfilene gir et fungerende eksempel på hvordan disse predikatene brukes med RDA-ontologien. Hvis du bygger din egen ontologi, kan du bruke dem som referanse.

6. Flere datalagre

Én GraphDB kan romme flere datalagre (repositories), hvert med sine egne data. Med Docker-installasjonen kan du legge til et datalager ved siden av EntEdit — for eksempel for å utforske en av eksempelsamlingene — og bytte EntEdit mellom dem. Arbeidet ditt i EntEdit berøres ikke. Alt du trenger, ligger på GitHub:

Hva Hvor på GitHub
Vokabular (påkrevd) database/types/ — tre mapper: entedit_profile, rda_vocabulary, term_vocabularies
Søkeindekser database/lucene_connectors/ — to SPARQL-oppdateringer
Eksempelsamlinger data/ — Ballard, Christie, Golding, Grass, Hamsun, McCarthy, Tolkien og Twain, én Turtle-fil hver

Opprette et datalager

  1. Åpne GraphDB Workbench på http://localhost:7200 (eller porten du har satt med GRAPHDB_PORT).
  2. Gå til Setup → Repositories → Create new repository → GraphDB Repository. Gi det en ID, for eksempel Hamsun, velg regelsettet RDFS-Plus (Optimized), kryss av for Disable owl:sameAs, og klikk Create.
  3. Velg det nye datalageret i datalagermenyen øverst til høyre i Workbench. Import og spørringer går alltid til det valgte datalageret.
  4. Vokabular: last ned prosjektet fra GitHub (Code → Download ZIP) og pakk det ut. Under Import klikker du Upload RDF files, velger alle filene i én av de tre mappene under database/types/ og importerer dem. Gjenta for de to andre mappene.
  5. Samling: under Import klikker du Get RDF data from a URL og limer inn filens råadresse, for eksempel https://raw.githubusercontent.com/trondaal/EntEdit/main/data/Hamsun.ttl. Flere samlinger kan ligge i samme datalager.
  6. Søkeindekser: åpne hver fil i database/lucene_connectors/ på GitHub, lim innholdet inn under SPARQL i Workbench og kjør det. Indeksene dekker data som importeres både før og etter.

Bytte EntEdit til et annet datalager

Knappen øverst i EntEdit viser navnet på datalageret som er i bruk. Klikk på den, endre slutten av SPARQL endepunkt-URL til ID-en for det nye datalageret — http://localhost/graphdb/repositories/Hamsun — og klikk Lagre. Bytt tilbake på samme måte med …/repositories/EntEdit. Grafvisningen følger datalageret EntEdit bruker.

Brukere og sikkerhet

I Docker-installasjonen er sikkerheten i GraphDB slått av: alle som når maskinens port 80 eller 7200, kan lese, endre og slette dataene. Du kan slå den på i Workbench under Setup → Users and Access ved å skru på Security, og deretter logge inn som admin (standardpassord root — bytt det med en gang). Der kan du legge til brukere og gi hver av dem lese- eller skrivetilgang per datalager.

EntEdit trenger da også tilgang. Enten slår du på Free access og gir lese- og skriverettigheter til datalagrene EntEdit skal bruke, eller du fyller inn brukernavn og passord under Brukernavn og Passord i innstillingene i EntEdit — de tas bare vare på så lenge nettleserøkten varer.

Brukere som er logget inn i Workbench, kan også sette opp grafvisningen, for eksempel hvilke relasjoner og hvilke språk for labels den viser; innstillingene deres brukes hver gang EntEdit åpner grafen.

7. Drifte GraphDB selv

I stedet for Docker-installasjonen kan EntEdit bruke en GraphDB du kjører selv — en frittstående installasjon, eller en server som deles av en klasse eller en organisasjon. Datalageret settes opp akkurat som i seksjon 6: opprett det med regelsettet RDFS-Plus (Optimized), importer vokabularet og dataene dine, og kjør oppdateringene for søkeindeksene, med Workbench på serverens adresse. Skal du opprette mange datalagre på én gang, for eksempel ett per studentgruppe, se Provisioning many repositories i ADVANCED.md.

Tips: Hvis du hopper over søkeindeksene, vil entitetleseren fortsatt fungere — du kan bla gjennom og redigere entiteter som normalt. Bare Søk-fanen krever Lucene-koblingene.

Koble EntEdit til serveren

Det finnes to oppsett som fungerer, og valget avgjør hva du må konfigurere.

GraphDB bak samme opprinnelse som applikasjonen — for eksempel applikasjonen på https://example.org/entedit/ og databasen på https://example.org/graphdb/repositories/EntEdit — er det beste valget: ingen CORS, ingen portnummer i endepunktet, og det fortsetter å virke når du tar i bruk HTTPS. To detaljer krever oppmerksomhet:

  • Workbench leverer <base href="/">, så når den nås under en sti-prefiks, slår filene den trenger opp mot roten av nettstedet og lastes ikke — resultatet er en side uten utforming. Enten setter du graphdb.external-url (og graphdb.vhosts hvis GraphDB kan nås på flere adresser) på GraphDB-serveren, eller du skriver om taggen i mellomtjeneren — Substitute i Apache, sub_filter i nginx.
  • Hold SPARQL-stien utenfor en slik omskriving. Omskriving krever at komprimering slås av mot bakenforliggende tjener, og det vil du ikke ha for spørreresultater: la /graphdb/repositories/ få sin egen regel som sendes videre urørt.

GraphDB på egen maskin eller port trenger ingen konfigurasjon av mellomtjener i det hele tatt, så lenge CORS er slått på i GraphDB. Workbench ligger da i roten av sin egen opprinnelse, og grafvisningen virker som den skal. Den eneste forskjellen er at hver bruker må velge datalageret sitt én gang i Workbench, siden EntEdit bare kan forhåndsvelge det når begge serveres fra samme opprinnelse.

På en delt server bør du slå på sikkerheten i GraphDB og gi hver bruker eller gruppe tilgang til sine egne datalagre, som beskrevet under Brukere og sikkerhet.

8. Utviklingsoppsett

For lokal utvikling av EntEdit-webapplikasjonen (uten Docker for frontenden):

  1. Sørg for at du har Node.js 20+ installert.
  2. Start en GraphDB-instans (enten via Docker eller en frittstående installasjon) med EntEdit-datalageret.
  3. Installer avhengigheter og start utviklingsserveren: 
    cd app
npm install
npm run dev
  4. Åpne http://localhost:5173 i nettleseren din.

Bruk endepunkt-URL-en http://localhost:7200/repositories/EntEdit, som peker rett på din egen GraphDB. Vite-utviklingsserveren videresender også /graphdb-forespørsler til http://localhost:7200, men foretrekk den direkte URL-en: grafvisningen åpner GraphDB Workbench, som bare vises riktig når den nås i roten av sin egen opprinnelse. Direkte tilkobling lar dessuten din egen GraphDB-installasjon være i fred — EntEdit skriver aldri til Workbench-innstillinger på tvers av opprinnelser.

Tips: Hvis du bare utvikler frontenden, kan du starte kun GraphDB-tjenesten med docker compose up graphdb graphdb-init -d og kjøre webapplikasjonen lokalt med npm run dev.

Prosjektstruktur

De relevante katalogene i EntEdit-prosjektet:

EntEdit/
├── app/ ← Webapplikasjon (inkl. nginx- og proxy-konfigurasjon)
├── data/ ← Eksempelsamlinger (ikke del av installasjonen)
├── database/
│ ├── types/ ← Vokabularfiler (lastes inn i GraphDB)
│ ├── testdata/ ← Eksempel-RDF-entiteter (eksempelgraf)
│ └── lucene_connectors/ ← Lucene-fulltekstindeksdefinisjoner
├── docker/
│ └── graphdb/ ← Datalagerkonfigurasjon + init-skript
└── docker-compose.yml

9. Feilsøking

Port 80 eller 7200 er allerede i bruk

Hvis et annet program på maskinen din — en webserver, IIS, en annen GraphDB — allerede bruker port 80 eller 7200, feiler up med «port is already allocated» eller «address already in use». Velg andre porter med variablene ENTEDIT_PORT (webapplikasjonen, standard 80) og GRAPHDB_PORT (GraphDB Workbench, standard 7200): 

ENTEDIT_PORT=8080 docker compose -f oci://docker.io/trondaal/entedit-compose:latest up -d

I PowerShell kjører du først $env:ENTEDIT_PORT=8080 og deretter kommandoen uten variabelen; i Ledetekst (Command Prompt) bruker du set ENTEDIT_PORT=8080. Applikasjonen ligger da på http://localhost:8080/entedit/, og endepunktet er http://localhost:8080/graphdb/repositories/EntEdit — det er bare porten som endres. Sett variabelen hver gang du kjører up, ellers flytter applikasjonen tilbake til port 80.

EntEdit får ikke kontakt med localhost:7200

GraphDB Workbench ligger på http://localhost:7200, og det er der du administrerer databasen, men det er ikke adressen EntEdit skal bruke som endepunkt. Nettleseren regner port 7200 som et annet nettsted — en annen opprinnelse — enn EntEdit selv, og blokkerer forespørslene med en CORS-feil. Adressen http://localhost/graphdb/... går via nginx, som videresender forespørselen til GraphDB på serversiden, og da oppstår ikke problemet.

Ingen klasser eller egenskaper vises

Datalageret mangler vokabularet, eller deler av det. Importer alle tre mappene i database/types/, som beskrevet i seksjon 5.

Søk-fanen finner ingenting

Datalageret har ingen søkeindekser. Kjør de to oppdateringene i database/lucene_connectors/ under SPARQL i Workbench med datalageret valgt; de indekserer dataene som allerede ligger der.

Workbench viser data fra et annet datalager

Workbench arbeider mot datalageret som er valgt i menyen øverst til høyre, uavhengig av EntEdit. Velg riktig datalager der før du importerer eller kjører spørringer.
